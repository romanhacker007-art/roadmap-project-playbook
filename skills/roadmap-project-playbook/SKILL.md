# Playbook: проект по маршрутной карте (из проекта VPS ↔ ноутбук)

Метод выработан в реальном проекте (перенос рабочих проектов на сервер, SSH, Tailscale, git, маршрутизация интернета).

## Метод (работает, переиспользовать)
1. **Маршрутная карта** `ROADMAP.md` в папке проекта: правила, таблица задач (№, зависимости, кто участвует, статус ⬜🟡⛔✅), раздел «Что сделать» по каждой задаче с блоком **Проверка**, промт для следующей сессии, журнал, заметки.
2. **FRAMEWORK.md** — 11 шагов на задачу: восстановить контекст → зафиксировать ограничения → факты (только чтение, «факт»/«догадка») → минимум 2 варианта → критика себя → перепроверка чисел → ревью до кода → минимальное изменение с откатом → проверка с негативным сценарием → запись итога → закрыть сессию промтом. Шаблон: `templates/FRAMEWORK.md`.
3. **Файл темы** `~/context/<тема>.md`: дата, цель, сделано, состояние (факт/догадка), решения пользователя, следующий шаг, промт, путь к переписке. Без паролей и ключей.
4. **Одна сессия — одна задача.** В конце: обновить карту и контекст, показать промт целиком в чате, остановиться, дать рекомендацию модели (см. `~/.claude/CLAUDE.md`).
5. Задача закрыта только после проверки выводом команд. Заблокированная задача получает ⛔ и причину.
6. Просьбу к пользователю формулировать так, чтобы шаг покрывал сразу несколько причин, команды давать одной строкой.

## Как стартовать новый похожий проект (быстро)
1. Создать `~/projekts/<имя>/ROADMAP.md` и `FRAMEWORK.md` по образцу `templates/FRAMEWORK.md`, заменить задачи.
2. Создать `~/context/<тема>.md`.
3. Сначала собрать факты о доступе (SSH/SFTP, ключи, сеть), потом остальное.
4. Решения пользователя записывать в карту сразу и не переспрашивать.

## Главные уроки проекта
- Доступ «закрыт по расписанию», а не «сломан»: сначала смотреть скрипты Open/Close-VPS-access, службу `sshd` и правило брандмауэра, а не гадать.
- `sshd` слушает только адрес Tailscale и может стартовать раньше него: ForceDaemon + перезапуск при сбое. После перезагрузки доступ возвращался через ~10 минут.
- Для Windows по SSH: cmd.exe, вывод в cp866; сложное — `.ps1` с BOM, класть через sftp во временную папку. Кириллица в PowerShell через SSH портится.
- Копирование через relay Tailscale обрывается: докачка (`reget`), по одному проекту.
- Интернет на ноутбуке: `.ru` напрямую, зарубежное через sing-box TUN → SOCKS на сервере. Работало в ручном режиме (кнопки «ЗАПУСК/ВОЗВРАТ интернета»), автозапуск отклонён пользователем. Потери UDP 12–17 % на пути Tailscale — причина осталась догадкой.
- Автопроверка прав блокирует git remote/restore без решения пользователя: показывать команду и причину.
- Ревью агентами лучше до кода; агенты могут оборваться по лимиту — не считать результатом.
